# Real-Time J1939 Verification Dashboard

`realtime_j1939_verifier.py` is a desktop dashboard that checks every received J1939 frame against `STM32F103_J1939_Signal_Generator.dbc`. It checks the 29-bit identifier, frame type, DLC, byte-level decoding, engineering range, configured expected values, message period, and timeouts.

## First run: dashboard simulation

```powershell
python realtime_j1939_verifier.py --simulate
```

Simulation proves that the DBC parser, byte decoder, timing checker, error display, and interface work before connecting hardware.

## Exact proof test

Use a fixed-value test mode in the STM32 firmware: Engine Speed = 1500 rpm, Vehicle Speed = 60 km/h, and Brake Pedal Position = 30 %. Start the dashboard with:

```powershell
python realtime_j1939_verifier.py --expected-profile verification_test_profile.json
```

The dashboard then fails immediately if any of those received values differs by more than half of one raw-bit resolution. Do not use this profile while the STM32 is running its current dynamic/random pattern mode; use it only for the known-value proof test.

## Direct CAN capture with Python

Install the optional CAN package:

```powershell
python -m pip install -r requirements.txt
```

Then start the dashboard using an interface supported by `python-can`. For a PCAN example:

```powershell
python realtime_j1939_verifier.py --interface pcan --channel PCAN_USBBUS1 --bitrate 250000
```

Do not run direct Python capture and TSMaster on a CAN adapter that allows only one active client. Use the TCP bridge below when TSMaster owns the interface.

## TSMaster Python Mini Program bridge

The dashboard always listens at `127.0.0.1:29500`. In a Python Mini Program CAN-receive callback, send each received frame as one JSON line over a localhost TCP connection:

```python
import json
import socket

def forward_to_verifier(can_identifier, data_bytes, timestamp_seconds):
    packet = {
        "id": f"0x{can_identifier:08X}",
        "data": bytes(data_bytes).hex(),
        "timestamp": timestamp_seconds,
        "extended": True,
    }
    with socket.create_connection(("127.0.0.1", 29500), timeout=0.05) as connection:
        connection.sendall((json.dumps(packet) + "\n").encode("utf-8"))
```

Create a Python Mini Program in TSMaster and use the callback function generated by that TSMaster version. Pass its received CAN identifier, eight data bytes, and timestamp to `forward_to_verifier`. The callback field names differ between TSMaster releases, but the bridge function is ordinary Python and does not depend on a vendor API.

## What PASS means

For a message to pass, it has the correct extended ID and DLC; every configured DBC signal decodes within its engineering range; it arrives at the expected interval; and, when a test profile is active, it matches the expected physical test value. A wrong byte, wrong scaling/offset, incorrect source-address ID, missing frame, or out-of-range signal produces a visible red error.
